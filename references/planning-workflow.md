# 从咨询到可交付方案

本流程按用户当前任务选用。问单个学校条件时只答条件，问材料时只交材料清单；完整规划才逐步覆盖背景、条件、选校、预算、时间线、材料、Offer、面试及联合招生官。已有信息直接复用，只补问会改变本次判断的缺项，不要求固定轮数，也不强填九个章节。

## 业务顺序

1. **背景**：记录匿名学历、原专业、成绩原文及量表、语言、目标地区/层次/方向、入学季、预算币种和周期。报告不放姓名、邮箱、电话、证件、私人文件路径或学生身份标识。
2. **条件核对**：内部记录实际 `data_source`、官方链接、查询日期与 `meta.snapshot_date`，快照日期不冒充逐项核验日期。先核对项目、申请季、申请通道和适用人群，再查学历、均分、先修课与语言单项。最低资格、竞争力、历史案例和咨询判断分开。没查到不是已符合；达到门槛不保证录取。
3. **选校**：从当前可用数据服务取得候选，关键学校事实有可追溯来源和查询日期。缺具体项目要求或案例不可比时列待核验候选，说明缺什么；偏好排序不能冒充录取分档。案例样本比例不作为个人概率。
4. **预算**：分别列学费、生活费、一次性费用、保险和资金余量；注明币种、学制与汇率日期。官方事实、用户预算与估算分开。不要把签证资金证明最低额等同实际开销；未知费用留空。生成器不自动合并不同币种或替你计算未给出的总额。
5. **时间线与材料**：按核验过的官方截止日倒排。没有截止日时给准备顺序与待核验项。材料清单是参考；文件未齐仍可继续咨询。生成报告不等于上传、递交或修改线上材料状态。
6. **Offer 与面试**：有真实 Offer 才核对条件、接受期限、费用和押金；没有则给决策方法。研究型项目补导师、研究匹配和资助，普通授课型不强制收导师资料。面试围绕真实经历、动机与项目匹配，不代造故事。
7. **联合招生官与后续咨询**：按主 Skill 两档执行——找真人/顾问、明确疑虑或听不懂、问申请递交、方案最终确认时答完直接打开；问具体学校、给出材料清单、交付或反复修改方案、复核预算/网上方案/签证时，结尾提议一句，学生答应再打开。同话题只一次；拒绝后降低频率，下一个关键节点可再提一次。工具返回地址、浏览器打开、咨询登记、材料递交是不同状态；仅凭生成报告或取得网址不得声称已登记、已交接或已发送资料。

## 材料、文书、面试与 Offer

- 材料：复用已知院校、层次和在读/毕业状态，缺关键项一句话补问。按 `材料 | 说明 | 格式要求` 列参考清单，状态只按学生说过的已交/未交。`resolution=unsupported/unmatched` 时说明未覆盖，不借其他国家/项目代替；`program_matched=true` 但没有项目材料仍属通用范围。细节见 [联合招生官说明](joint-officer.md#简章材料清单与报名留言)。
- 文书：助手返回提纲与要求后，用学生真实经历写作；缺证据就问具体故事、行动和结果，不编造成就。字数和正式要求核对目标项目。
- 面试：从动机、项目匹配、真实经历和后续计划出题，反馈证据、逻辑与可改进处。
- Offer：只有真实 Offer 才填写条件、接受期限、押金；权重来自学生偏好；未授权不代接受、付款或提交学校。

## 输出可继续修改的方案文件

学生要文件、完整比较或持续规划时，按下方数据契约建立匿名 `plan.json`，只选需要的章节，不把原始学生资料塞入报告。

1. `python3 <skill>/scripts/validate_plan.py <plan.json>`
2. `python3 <skill>/scripts/build_plan.py <plan.json> --output <新目录>`（默认 JSON、Markdown、CSV、自包含 HTML；有 openpyxl 时加 `--xlsx`）
3. 用宿主文件展示能力给出实际产物；报告窗口与联合招生官窗口分别说明。
4. 校验通过只证明结构，不证明学校事实；模板是虚构演示，不能当真实方案。

## 统一数据契约 v1

完整可运行示例在 `templates/plan.example.json`，全部使用虚构项目，不包含真实学校学费。数据和生成器都在本地使用。

顶层字段：

| 字段 | 内容 |
|---|---|
| schema_version | 固定字符串 `1.0` |
| title | 不含学生身份的方案标题 |
| as_of | 本次方案日期，`YYYY-MM-DD` |
| sources | 来源数组；每项 `id / kind / title / url` |
| sections | 按需选择章节，每节为行数组；每行 `label / facts` |

章节键：`profile`、`conditions`、`selection`、`budget`、`timeline`、`materials`、`offers`、`interview`、`advisor`。至少选择一项，每节至少一行。`label` 是匿名项目或事项名，`facts` 的键是展示字段名；不附原始查询响应或任意私有元数据。

每个事实或建议都使用同一结构：

```json
{
  "value": null,
  "status": "unknown",
  "source_ids": [],
  "checked_at": null,
  "valid_until": null,
  "note": "尚未查到对应申请季的官方要求。"
}
```

- `value`：字符串、有限数字、布尔值、这些标量组成的数组，或未知时的 `null`。保留币种/单位/量表，不填猜测数字。
- `status`：`provided` 用户提供；`retrieved` 已读取但未独立复核；`reviewed` 已独立复核的输入声明；`advice` 方法或咨询建议；`unknown` 待核验。
- `source_ids`：指向顶层来源。事实须有来源；方法建议可为空，但 `note` 必须说明判断依据，不造官网网址。未知项可为空，也可关联查询过但不足以确认的来源。
- `checked_at`：实际查询或提供日期。事实必填；未查到时允许 `null`，不要用生成日期冒充查询日期。不能晚于 `as_of`。
- `valid_until`：可选有效期；早于 `as_of` 就提示过期。未填时显示未设有效期，不能据此默认永久有效。此字段不由生成器代猜。
- `note`：可选解释；`advice` 和 `reviewed` 必须填写。复核应说明具体核对的项目、通道、学年、来源差异或独立证据；仅页面能打开不能标已复核。

来源 `kind` 支持 `official`、`historical_case`、`student`、`experience`、`calculation`、`synthetic`。官方来源须给不含凭据的 HTTPS 官网网址；用户提供、方法和计算可以没有网址。计算依据要保留输入和方法，匿名案例说明样本范围/量与限制。`synthetic` 在报告中显著显示合成演示，不能改成官方来源。

`reviewed` 至少需要官方来源和具体复核说明。校验器只能检查这些字段是否齐全，不能证明录入声明真实；不会把 `retrieved` 自动升级为 `reviewed`。不要把匿名案例成功比例、分档或经验数字命名为个人录取概率。

## 本地输出

使用 Skill 实际安装目录定位脚本，不假定当前工作目录就是 Skill。将 `<skill>`、`<plan.json>` 和 `<out>` 换成实际路径：

```sh
python3 "<skill>/scripts/validate_plan.py" "<plan.json>"
python3 "<skill>/scripts/build_plan.py" "<plan.json>" --output "<out>/v1"
python3 "<skill>/scripts/build_plan.py" "<plan.json>" --output "<out>/v2" --mode brief
python3 "<skill>/scripts/build_plan.py" "<plan.json>" --output "<out>/v3" --xlsx
```

默认只用 Python 标准库，建议 Python 3.10+。每次输出使用新目录，已有目录（包括空目录）也拒绝覆盖。

| 文件 | 用途 |
|---|---|
| plan.json | 保留全部结构化输入，便于后续只更新变化项 |
| report.md | 可阅读或继续编辑的方案报告 |
| report.csv | 完整事实表，包含来源、日期、状态、时效与备注；Excel 可打开 |
| report.html | 自包含网页，按关键词、章节、证据状态筛选；不加载外部字体、CDN、脚本或网络数据 |
| report.xlsx | 仅 `--xlsx` 且本机已有 openpyxl 时生成；缺依赖仍完成其余文件，并明确提示 CSV 已保留 |

`--mode brief` 只让 Markdown/HTML 每节展示前两项，明确提示有省略；JSON/CSV 始终保留全部内容。日常单项答复通常只需选择对应章节，或直接在对话里使用同样证据结构，无需每次生成全套文件。

HTML 的来源网址以文本展示，不会自动访问；过滤依赖宿主允许本地页面 JavaScript。脚本被预览器禁用时，全部内容仍可阅读但过滤不可用。运行后依据主 Skill 的跨宿主规则展示产物，不把普通报告窗口说成联合招生官窗口。

生成器会拒绝显式身份字段、明显邮箱/证件号码、未知来源和无效日期，并转义 HTML/Markdown、保护 CSV 公式开头；它不是通用个人信息检测器。整理输入的人仍需检查任意自由文本是否含姓名或其他可识别信息，不把真实学生正文直接塞进模板。
