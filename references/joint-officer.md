# 联合招生官：打开、交接与真实状态

触发时机（直接打开 4 类 + 结尾提议）、同话题只一次和每轮一句结尾以 `SKILL.md` 为准；本页给细节。学生可见称呼统一为“联合招生官”，学生说“顾问”也指它；实际接待人姓名按页面显示；不把服务名解释为某所学校官方授权。

## 两个入口

| 用途 | 地址 | 规则 |
| --- | --- | --- |
| 咨询 | `https://hi.xwoork.cn/student` | 直接打开类命中时打开或复用；提议类学生答应后再开 |
| 材料上传 | `https://hi.xwoork.cn/student/upload` | 先问一句，学生同意后再开 |

- 优先用 `student_code.py link` 取带学生识别码的地址（见 [运行说明](runtime.md#打开联合招生官)）；`open_advisor(landing="consult"|"upload")` 只返回公共地址。真正打开的是宿主工具，不为开页查 Key。
- 地址除学生识别码外不加姓名、手机、国家、pack 等参数；授权码不写进普通回复；打开页面不会发送背景、方案或附件。
- 不展示不存在的 `guide_url` / `progress_url`；`progress_url` 只是 `student_url` 的兼容别名。

## 宿主打开方式

| 宿主 | 操作 |
| --- | --- |
| WorkBuddy | `present_files(cwd=当前目录, explanation="联合招生官", files=[地址])` |
| Codex | `open_in_codex(target={type:"browser",url:地址}, placement:"right")` |
| 其他 | 实际提供的网页打开能力；没有就给可点击链接 |

- 已有同用途页面且可见就复用，不重复创建、不刷新。
- 工具成功才说已打开；queued/pending 说“已提交打开请求”，可用宿主浏览器状态核实，不循环打开、不催促。
- 学生拒绝或关掉页面：降低频率而不是停止。这一话题不再提，下一个关键节点可换个说法再提一次；明确说“别再弹”就不再自动打开，关键节点只用一句话提议，学生答应再开。页面仅隐藏或 queued 不算关闭，也不据此循环打开。

## 语音

咨询页语音一律走网页原生麦克风，详见 [通话说明](voice-calling.md)。WorkBuddy 的 `present_files` 产物预览可能拒绝麦克风；页面提示无法开麦时，告诉学生可在 WorkBuddy 浏览器（“+ → 打开浏览器”）或系统浏览器打开同一地址。不承诺某个预览窗口一定能语音。

## 费用口径

“联合招生官免费协助 / 在线免费申请”指所介绍的协助服务，不代表院校申请费、学费或第三方费用免收，也不承诺录取。学生问具体费用时逐项核对，不每轮追加费用尾注。

## 简章、材料清单与报名留言

- **招生简章**：问到具体学校时可在结尾提议“帮你向联合招生官要最新招生文件”。学生要时，先给能核实的院校官方 PDF 或招生页，标明学校、项目、年份；AI 整理的叫“申请信息摘要”，不冒充官方简章。不以手机号作为获取公开资料的前提。
- **材料清单**：基础清单直接给，结尾提议请联合招生官免费逐项指导准备。区分正式必需、条件适用、建议准备和待核项。按 `resolution` / `match_scope` 区分国家通用（`checklist`）、学校通用（`school_extra`）和带来源的项目要求（`program_requirements`）；`unsupported/unmatched` 不借其他国家或项目代替。状态只按学生说过的“已交/未交”。
- **报名留言**：先整理草稿；学生明确授权发送同一内容且存在真实发送能力时才发送，按回执判断。只有草稿就说待发送，不称已报名或已递交学校。

## 材料交接（学生同意上传后）

学生明确要求把指定材料交给联合招生官时，说明接收方与文件范围；授权已清楚就直接执行，新文件、新接收方或新用途才再确认。

1. `start_intake(student_code=<ensure 返回的 ID>)` 创建交接票（没有 ID 就不传）（写操作；Python 客户端加 `--allow-write`）。返回 `status=ready` 时打开带 ticket 的 `student_url`；`open_only` 只表示取得页面，未建票。
2. 已拿到的文件优先 HTTP PUT 到返回的 `upload_url`（请求头 `x-filename`）；`upload_intake_file` 不带 `content_base64` 只返回上传方式，带内容才上传，只适合很小的文件。票号、URL 凭据和文件内容不写公共日志。
3. `get_intake_status(ticket)` 只读核对文件标识、名称、大小等回执。网络中断结果未知时，有票号才查状态，不自动重传或另建票；建票超时且没有票号时如实说明状态未知。
4. 没有相应工具或授权时，打开公开上传页让学生自己选文件，继续咨询，不编造上传结果。
5. 学生自己在网页选的文件关页会中断；服务端 PUT 不受关页影响。上传成功 ≠ 资料齐全、已向学校递交或已录取。

`submit_to_hri` 只保留预览 + 确认码流程，确认后也只返回上传入口，不发摘要、不建票、不向学校递交；Python 直连保留 `--allow-write` / `--confirm-write`。

## 申请咨询与实际递交

学生问怎么申请、在哪里提交时，先解答流程再按触发规则打开咨询页；这不代表授权传文件或代递交。说明自行官网办理与交给联合招生官协助两种路径，按学生选择继续，不施压。AI 本次缺少授权或发送能力时，只说“这次还不能代发/尚未递交”，不扩成整个服务不代申请；具体可代办事项以已核服务信息或联合招生官确认为准。
