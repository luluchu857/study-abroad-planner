# 在线顾问与语音通话

本页用于学生要通话、网页无法获取麦克风，或询问通话助手时。打开咨询页面、开始采音、发起通话、双方接通是不同状态。

## 当前顺序

1. Skill 按主说明打开 https://hi.xwoork.cn；这一步只展示咨询入口。
2. 学生在页面中点击拨打 / 接听时，由网页处理麦克风和通话。当前页面优先尝试宿主允许的原生媒体能力，已有权限按系统状态复用。
3. 对确实阻止原生麦克风的容器，页面才进入受限环境的助手检查 / 权限处理。不能只因应用叫 WorkBuddy 就认定麦克风不可用。
4. 只有真实媒体链路和页面状态确认接通，才说通话已建立。没有权限、助手不可用或连接失败，按具体状态说明，不把健康检查或麦克风音量条当作双向通话。

当前助手探测仍只识别旧测试服务的健康标识，没有正式双向媒体或配对能力验证，且唤起分支不等待成功回执。因此页面显示“通话助手”也不能证明音频已经接通。当前受限提示会建议系统浏览器，但没有完成自动打开现有咨询室的回落流程。PiS 自身原生不可用时走应用权限指导，不切助手；普通采音被拒绝也不等于一定切换助手。

维护记录中，2026-10-22 已有 Windows WorkBuddy 与 Mac 顾问真实双向通话，使用的是原生网页媒体，测试助手当时未运行。不同版本和容器仍需分别检查，不能由一次成功推断所有版本都可用。

## 旧“通话助手”的实际能力

工程中曾有 Windows 用户级安装 / 启动脚本，以及 Python / PowerShell 本地麦克风测试页面。它能展示本机采音与音量，不包含正式的双向媒体、远端播放或咨询配对。当前 Skill 不把这些测试脚本作为可用通话助手分发。

旧启动动作可能进一步开始本地测试采音，不是单纯打开一个待机窗口。因此：

- 打开顾问链接时，不自动运行旧助手、唤起旧 `pis-voice` 测试协议或开始录音。
- 不自动下载安装来源不明的助手，也不修改浏览器 / 系统麦克风权限。
- 原生通话受限时，明确说明当前容器的问题；按当前页面与宿主的权限指引处理。用户选择系统浏览器时使用现有咨询入口，不能声称背景或材料已转交。
- Python MCP 直连解决的是信息查询连接，不负责传输通话音频，不能代替麦克风权限。

## 将来正式助手的接入条件

如果后续发布真正的通话助手，应先确认可信安装来源、安装版本、咨询配对及双向媒体能力，并将“启动待机”与“开始采音 / 通话”分开。网页在确认原生受限后再按实际协议唤起；用户开始或接听通话后才请求设备权限与传输音频。

在这些能力完成并验收前，不向学生承诺“打开顾问时会自动安装 / 启动助手并保证通话”。
