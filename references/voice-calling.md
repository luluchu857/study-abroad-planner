# 在线顾问与通话助手

学生要拨打 / 接听、网页无法获取麦克风，或需要使用助手时阅读本页。公共咨询入口为 **https://hi.xwoork.cn**，通话助手固定为 **https://hi.xwoork.cn/voice-helper**。

助手是系统浏览器中的 HTTPS 采音和播放页面。它通过配对接续原咨询页的同一次通话，原页面继续显示聊天和资料；不需要安装 Python 音频程序、浏览器扩展或本地后台服务。包内 Python MCP 客户端负责查询等业务，不负责音频。

## 先判断是否需要助手

- 用户开始 / 接听时，原咨询页先尝试当前宿主提供的原生麦克风能力。不能仅凭“WorkBuddy”或“内嵌浏览器”名称认定不可用。
- 系统权限框仍未答复、浏览器显示等待时，保持等待或由用户取消。没有任意等待秒数能证明权限已拒绝；不重复请求、不自动开第二条媒体链路。
- 页面明确没有麦克风 API、权限被拒绝、容器政策禁止，或用户明确选择「使用通话助手」时，进入下面流程。拒绝权限不等于授权助手开麦，助手仍须用户单独允许。
- 顾问端原生权限问题按顾问应用指引处理。这里的配对助手用于学生一侧，不把顾问自动切到学生助手。

## 配对与通话

1. **保留原咨询页面。** 在原页面使用「使用通话助手」入口，或按当前页面提示进入「连接通话助手」。不创建新的咨询来代替当前咨询。
2. **用系统浏览器打开** `https://hi.xwoork.cn/voice-helper`。若宿主把新窗口仍放在内嵌容器中，使用其“在浏览器打开”功能或实际可用的 Chrome / Edge / Safari 打开能力。只有内嵌打开工具时，把固定链接交给用户在系统浏览器打开，不声称已经打开系统浏览器。
3. 在助手点击 **「准备配对」**，取得 **10 位配对码**。仅打开网页或生成配对码不会自动开始通话。
4. 回到原咨询页，将配对码填入 **「助手配对码」** 并点击 **「确认配对」**。配对码只用于当前配对，不放进报告、公开文件或分享链接。
5. 回助手点击 **「启用语音」**，由用户确认系统麦克风权限。准备阶段会检查采音能力；只有本次通话获授权并接通后才传输通话声音。仍在等待系统答复时，不重复点击或切换别的采音方式。
6. 在原咨询页面完成 **开始 / 接听**。若这次配对来自已点击的开始 / 接听操作，页面会继续该次操作，不再重复拨号。若仍显示按钮，则按当前状态完成一次；配对本身不会自动接听下一通来电。
7. 助手显示麦克风与顾问声音状态，提供 **「静音 / 取消静音」**、**「播放顾问声音」** 和 **「停止 / 挂断」**。浏览器阻止自动播放时，在助手点击播放。双方实际能听到且状态匹配，才报告双向通话成功。

主咨询页和助手页在通话期间都保持打开。关闭助手会停止该窗口的本机声音；结束通话仍以主页面 / 助手的实际结束回执为准。配对过期、原咨询页失效、退出或通话更换后，需要重新确认，不能沿用旧配对加入另一通话。

## 让状态与事实一致

| 看到了什么 | 可以怎样说明 | 不能据此说明什么 |
| --- | --- | --- |
| 系统浏览器显示助手页面 | 助手已打开，尚待配对 | 已采音、已接通 |
| 出现配对码 / 配对确认 | 当前助手与原咨询页已配对 | 已允许麦克风、双方已通话 |
| 浏览器权限允许、助手准备完成 | 麦克风准备完成，等待本次通话 | 对方已接听、对方一定能听见 |
| 静音命令已提交 | 已发送静音设置，等待助手实际状态 | 麦克风已经停止发送 |
| 实际媒体连接、对端声音可听 | 当前这次通话已接通 | 所有设备、网络和应用版本都可用 |
| 停止 / 挂断回执未确认 | 本机声音已停或结束待确认，按真实状态说明 | 对端或服务端一定已结束 |

不要用健康接口、配对码、麦克风音量条或单侧“已连接”代替真实双向听感。新助手采用 RTC，必要时经 TURN 中继；这不保证所有网络都能连接。

## 常见问题

- **原生权限一直等待**：提醒检查系统权限框；允许或取消由用户完成。不把 pending 当故障，也不另开助手抢占设备。
- **系统浏览器也拒绝麦克风**：说明当前浏览器 / 系统的实际拒绝状态，引导用户按页面权限提示处理；不要代改系统权限，不循环采音请求。
- **配对码失效或页面已更换**：终止旧配对，再在当前助手准备一个新码，由当前原咨询页重新确认。
- **已配对但没有声音**：分别看本次通话是否已接听、助手是否已启用语音、是否静音、是否提示点击播放。只诊断当前可见状态，不反复创建通话。
- **撤销、断线或结束未确认**：按页面重试 / 重新配对入口继续；旧操作返回较晚也不能影响后来通话，不说已自动恢复。
- **系统浏览器打不开**：提供固定 HTTPS 链接和简短步骤；不要下载未知助手或把原咨询页的身份令牌、Cookie 放入 URL。

## Agent 安装与验收

安装 Skill 和查询 MCP 时，不必安装任何语音程序。当前网页提供助手界面；无需向客户端另登记一个“语音 MCP”。安装阶段最多核对固定入口、页面内容和功能说明，不自动配对、请求设备权限或拨打真实咨询。

只有用户明确要实际通话，才继续配对及媒体验证；系统麦克风权限仍由用户确认。验收逐项记录：系统浏览器是否打开 → 原页是否配对 → 麦克风是否获准 → 本次通话是否接通 → 双向声音是否实听 → 静音 / 播放 / 挂断是否真实生效。未做的项写“未验证”，不把合成测试补记为真人验收。

v0.9.0 对这条新助手链路已有合成验证；本版真实设备、具体 WorkBuddy 版本和网络听感待分别验收。历史上某个 WorkBuddy 原生网页通话成功，不等于本次新助手已完成该设备验收。

旧 `localhost:18976` 健康检查、`pis-voice` 测试协议、Python / PowerShell 采音样稿不是本次助手。不要安装、唤起或检查这些旧测试工具来证明正式通话成功。
